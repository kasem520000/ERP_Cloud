# تطبيق مندوب التوزيع — أندرويد (Kotlin + Jetpack Compose)

تطبيقٌ أصليٌّ كاملٌ لمناديب التوزيع (بيع متنقّل)، مبنيٌّ على **Kotlin وJetpack Compose**،
ومتوافقٌ **حرفيًّا** مع مسارات الخادم الخمسة عشر الموثّقة في:

- `docs/ANDROID_REP_APP_API_REFERENCE.md` — المرجع الكامل للمسارات والأجسام ورموز الأخطاء.
- `docs/ANDROID_REP_APP_API_RESPONSES.json` — أمثلة الردود والخطأ.

لا يُخترَع في التطبيق رقمٌ ولا مسارٌ ولا حقل: كلُّ كميةٍ ومبلغٍ يأتي نصًّا من الخادم
(numeric من PostgreSQL)، ولا تُحسب أيّ قيمةٍ في العميل — بعد كلّ إجراءٍ ناجحٍ تُعاد
قراءة `GET /van-sales/me` كما تفعل شاشة الويب.

---

## ١) الفتح والبناء (محليًّا)

المتطلّبات:

- **Android Studio** (Ladybug أو أحدث) مع **JDK 17** (مضمّن في Studio).
- Android SDK 35 (يُنزله Studio تلقائيًّا عند أوّل مزامنة).

الخطوات:

1. من شاشة ترحيب Android Studio: **Open** ← اختر مجلّد `apps/android-rep`
   (لا جذر المستودع — هذا المشروع مستقلٌّ عن بيئة pnpm ولا يحتاج Node).
2. انتظر مزامنة Gradle (أوّل مزامنة تنزّل الاعتماديّات).
3. **Run ▶** على محاكّي أو جهاز حقيقيّ.

من سطر الأوامر:

```bash
cd apps/android-rep
./gradlew assembleDebug        # الناتج: app/build/outputs/apk/debug/app-debug.apk
```

## ٢) البناء عبر GitHub Actions (بلا أيّ إعدادٍ محليّ)

هذا المشروع جاهزٌ للرفع إلى مستودع GitHub جديد والبناء سحابيًّا:

1. **أنشئ مستودعًا جديدًا** على GitHub (فارغًا، بلا README).
2. ارفع **محتويات مجلّد `apps/android-rep` في جذر المستودع** — بحيث يكون
   `gradlew` و`app/` و`.github/` في الجذر مباشرةً:

   ```bash
   cd apps/android-rep
   git init && git add . && git commit -m "تطبيق مندوب التوزيع"
   git remote add origin https://github.com/<حسابك>/<المستودع>.git
   git branch -M main
   git push -u origin main
   ```

3. اذهب إلى تبويب **Actions** ← **Build APK** ← **Run workflow**.
4. بعد دقائق ستجد ملفّي APK (debug + release) في قسم **Artifacts** جاهزين للتحميل
   والتثبيت.

ملفّ الـworkflow في `.github/workflows/build-apk.yml` يتحقّق من سلامة Gradle Wrapper،
يبني نسختي debug وrelease، ويرفعهما كـArtifacts (تحتفظ بها ١٤ يومًا).

### توقيع نسخة الإصدار (اختياريّ — للنشر الرسميّ)

لا تضع مفتاح التوقيع في الكود أبدًا:

```bash
keytool -genkeypair -v -keystore release.keystore -alias rep \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 release.keystore        # انسخ الناتج
```

ثم في **Settings ← Secrets and variables ← Actions** أضف أربعة أسرار:

| السرّ | القيمة |
| --- | --- |
| `KEYSTORE_BASE64` | ناتج `base64` أعلاه |
| `KEYSTORE_PASSWORD` | كلمةُ ممرِّ المخزن |
| `KEY_ALIAS` | `rep` |
| `KEY_PASSWORD` | كلمةُ ممرِّ المفتاح |

مع هذه الأسرار تُوقَّع نسخةُ الإصدار تلقائيًّا؛ وبدونها تُوقَّع بمفتاح التصحيح كي
تُثبَّت مباشرةً للتجربة (يمكن تثبيتُها بجانب نسخة أخرى فقط عند توافق التوقيع).

## ٣) تهيئة الخادم

يُدخل المندوبُ عنوانَ الخادم في شاشة الدخول (يُحفظ ولا يحتاج إعادة بناء):

- **محاكّي أندرويد:** الجهاز المضيف هو `10.0.2.2` — الافتراضي
  `http://10.0.2.2:3000` (يُلحق التطبيقُ `/api/v1` تلقائيًّا).
- **جهاز حقيقيّ على شبكة المنشأة:** عنوان الخادم في الشبكة المحليّة، مثل
  `http://192.168.1.10:3000`.
- الاتصال `http` على الشبكة المحليّة مسموحٌ في البيان (`usesCleartextTraffic`)
  لأنّ خادم المنشأة في LAN غالبًا بلا TLS.

الدخول: البريد + كلمة المرور + **رمز المنشأة (tenantCode)** + رمز التحقّق الثنائيّ إن
كان مفعّلًا. تجديدُ الرمز صامتٌ (401 ⇒ refresh ⇒ إعادة المحاولة مرةً واحدة)، وفشلُه
يعيد إلى شاشة الدخول.

### حفظُ بيانات الدخول والدخول بالبصمة/النمط

- **«تذكّرني»** (افتراضيًّا مفعّل) يحفظ البريدَ ورمزَ المنشأة وكلمةَ المرور بعد أوّل
  دخولٍ ناجح — **مشفَّرةً بمفتاح Android Keystore** (EncryptedSharedPreferences)،
  لا نصًّا صريحًا على القرص، فتُجد الحقولُ معبَّأةً في المرّات التالية.
- **«الدخول بالبصمة / نمط الهاتف»** فوق ذلك: في المرّات التالية يعرض التطبيقُ مصادقة
  `BiometricPrompt` فورَ فتحه — بصمةً أو وجهًا أو **نمط/رمز الهاتف** (أندرويد ١١+؛
  وما قبله بصمةٌ فقط) — وبنجاحها تُفتح الجلسةُ بلا كتابةِ شيء.
- «نسيانُ هذا الحساب» من شاشة الدخول يمحو الحفظَ كلَّه (مفاتيحُ وإعدادات).
- **تغييرُ كلمة المرور** من مساحة العمل (`POST /auth/change-password`) بسياسة الخادم
  نفسها (١٢+ محرفًا، ٣ فئات، لا بريد ولا اسم)؛ وبعده يُسجَّل الخروجُ من كلّ الأجهزة
  (سياسةُ الخادم) وتُحدَّث الكلمةُ المحفوظة تلقائيًّا.

## ٤) الشاشات

| الشاشة | المسار/الغرض |
| --- | --- |
| تسجيل الدخول | شعارٌ وهويّة + بيانات الخادم + تذكّرني + بصمة/نمط |
| مساحة العمل | ترويسةُ هويةٍ (المندوب/السيارة/المنشأة) + شبكةُ إحصاءات + القوائم بالنوافذ |
| بيعٌ جديد | من أمر تحميل المندوب؛ عميلٌ ببطاقة أو نقديّ؛ ضريبية/تسليم داخليّ؛ نقديّ/بطاقة/آجل |
| مرتجعُ عميل | على مستند بيعٍ أصليّ (لا مرتجعَ مرتجع)، والسقفُ = المبيع + البونص − ما أُرجع سابقًا |
| تحصيلُ دين | على فاتورة آجلة غير مسدَّدة، والمبلغُ لا يتجاوز المتبقّي |
| تأكيدُ استلام توريد | يبدأ العهدة؛ الكميّة فارغة = اعتماد الحمل كاملًا، وأيّ فرقٍ يُسجَّل نقصَ استلام |
| إغلاقُ الوردية | مرتجع/تالف/نقد + جرد المركبة كلّها **أو** الجرد لهذا الأمر وحده (لا الاثنان معًا) |
| طباعةُ الفاتورة | نسختان (العميل/المندوب الموقَّعة) — نظام أندرويد أو PDF، مشاركة PNG، حراريّة ESC/POS |
| مركزُ الإشعارات | صندوقُ العضويّة الرسميّ (`GET /notifications`) مع غيرِ المقروء وتعليمِ المقروء |
| طابورُ النيّات | ما حُفظ دون اتصال: بانتظار/وصلت/مرفوضة + إعادة الإرسال بترتيب الإدخال |
| طابعاتُ البلوتوث | الأجهزةُ المقترنة + عرضُ الورق ٥٨/٨٠ملم |
| تغييرُ كلمة المرور | بسياسة الخادم الحيّة، وتسجيلُ خروجٍ تلقائيّ بعد النجاح |

البواباتُ على أذون الخادم: `van_sales.view` للمساحة، `van_sales.invoice.create`
للبيع والمرتجع، `van_sales.collection.create` للتحصيل، `van_sales.closing.submit`
للإقفال، `tenant.notification.view` لمركز الإشعارات — والأزرارُ تُقفل لا تُخفى.

## ٥) نظامُ الإشعارات

1. **مركزُ إشعارات داخليّ** — من `GET /notifications` (أحدث ٥٠) مع `meta.unread`،
   وتصنيفٌ الكلّ/غيرُ المقروء، وتعليمُ المقروء فرديًّا أو كلًّا (`POST /notifications/{id}/read`
   — تكرارٌ آمن في الخادم). شارةُ الجرس في مساحة العمل تعرضُ غيرَ المقروء.
2. **إشعاراتُ نظام أندرويد محليّة** (قناتان: «الطابور دون اتصال» و«التوريد والاستلام»):
   - عادت الشبكة وهناك نيّاتٌ معلّقة → «لديك N نيّةً تنتظر الإرسال».
   - وصلت نيّاتٌ بعد إعادة الإرسال → إشعارٌ بعدد الواصل.
   - توريدٌ جديدٌ بانتظار استلامك → إشعارٌ عالي الأولوية (مرّةً واحدةً لكلّ أمر).
   - إذنُ الإشعارات يُطلب وقتَ التشغيل على أندرويد ١٣+ من مساحة العمل.
3. إشعاراتُ الخادم **دفعيّة داخل الردود** لا Push (لا FCM في الخادم) — التطبيقُ
   يعرضُها لحظةَ كلّ تحديثٍ ولا يبتلعها.

## ٦) العمل دون اتصال — النيّة الواحدة مفتاحٌ واحد

- **البيع والمرتجع والتحصيل** (المسارات التي تقبل `idempotencyKey`): عند انقطاع
  الشبكة أو خطأ ٥xx تُحفظ النيّةُ في طابورٍ محليّ (`filesDir/offline_queue.json`،
  كتابةٌ ذرّيّة) **بمفتاحها نفسه وجسمها كما أُرسلا**، والمفتاحُ ينجو من موت العملية.
  رفضُ الخادم (4xx) لا يُحفظ — يُعرض نصُّ `detail` العربيّ حرفيًّا.
- **إعادة الإرسال** بترتيبِ الإدخال لا بترتيبِ النقر. `409 IDEMPOTENCY_REPLAY` يوقف
  النيّةَ بحالة «مرفوضة تحتاج قرارك» ولا يُعاد إرسالها عمياءً.
- **تأكيد الاستلام وإغلاق الوردية لا يُحفظان دون اتصال** — عمدًا: مساراهما بلا مفتاح
  عدم تكرار، فإعادةُ إرسال الاستلام تُرفض 409 وتُظهر نيّةً ناجحةً خطأً، وإعادةُ إعلان
  الجرد تعيد كتابةَ إعلانٍ بانتظار المحاسب. الزرُّ يُقفل دون اتصال برسالةٍ تشرح السبب.

## ٧) الطباعة والفاتورة الاحترافيّة

من شاشة طباعة الفاتورة (تقرأ `print-view?copies=2`):

1. **طباعة نظام أندرويد / حفظ PDF** — عبر `PrintHelper` (أيّ طابعةٍ مثبَّتة).
2. **مشاركة صورة PNG** — عبر FileProvider إلى واتساب/البريد/…
3. **طابعة حراريّة Bluetooth (ESC/POS)** — بلا مكتبات خارجيّة: تُرسل صورةُ الفاتورة
   نقطيّةً (`GS v 0` على شرائط) فتخرج العربيّةُ سليمةً على أيّ طابعةٍ حراريّة.

تخطيطُ الفاتورة بأسلوب إيصالات ZATCA: ترويسةُ المنشأة (الاسم/الرقمُ الضريبيّ/السجلّ/
الهواتف)، شريطُ عنوانِ المستند، صفوفُ بياناتٍ ثنائيّةَ الأعمدة بفواصلَ منقّطة، الإجماليُّ
المستحقُّ داخل إطارٍ ملوّنٍ خفيف، و**رمزُ QR داخل إطارٍ مع تسميته** — والرمزُ يُبنى من
`qrPayload` كما يرسله الخادم (لا يُولَّد في التطبيق)، وخانتا توقيعٍ (عميل/مندوب) في
نسخة المندوب.

## ٨) بنية المشروع

```
app/src/main/java/com/erpcloud/rep/
├── MainActivity.kt        التنقّل (Navigation-Compose) + RTL دائم (FragmentActivity للبصمة)
├── RepApp.kt              حاوية الاعتماديّات اليدويّة (AppContainer)
├── util/Dec.kt            تعامل decimal مع كل أرقام الخادم (نصوص)
├── data/api/              العقود (auth/notifications/van/print/requests) + RepApi + Network
├── data/offline/          SessionStore (DataStore) + CredentialStore (Keystore) +
│                          Idempotency + QueueStore
├── data/RepRepository.kt  كل النداءات + أحكام الطابور (ActionResult)
├── platform/AppNotifier.kt  قنواتُ إشعارات النظام وإرسالها
├── printing/              InvoiceBitmap (Canvas+QR) + EscPos + InvoicePrint
└── ui/                    AppViewModel واحد + شاشات + مكوّنات مشتركة
```

لا Hilt ولا Room ولا مكتبات طباعة: DI يدويّ، وطابورُ ملفٍّ واحد. الأيقونةُ باصُ
توزيعٍ متجهيٌّ (adaptive للأندرويد ٨+ مع monochrome، وبديلٌ كاملٌ لما قبله).

## ٩) الأذونات

- `INTERNET` / `ACCESS_NETWORK_STATE` — الشبكة ومراقبة الاتصال.
- `POST_NOTIFICATIONS` (١٣+) — إشعاراتُ النظام، تُطلب وقتَ التشغيل.
- `USE_BIOMETRIC` — البصمة/نمط الهاتف عبر BiometricPrompt.
- `BLUETOOTH` + `BLUETOOTH_ADMIN` (حتى API 30) و`BLUETOOTH_CONNECT` (31+) —
  الطابعة الحراريّة، وإذنُ 31+ يُطلب من شاشة الطابعات.
- `usesCleartextTraffic` — خادم LAN بـhttp. و`allowBackup=false` — لا نسخَ احتياطيًّا
  لبيانات جلسةٍ أو كلماتِ مرور.

## ١٠) ملاحظاتٌ للتشغيل التجريبيّ

- المحاكّي: شغّل الخادم على الجهاز المضيف (المنفذ 3000) واستخدم `10.0.2.2:3000`.
- جهاز حقيقيّ: الخادمُ والهاتفُ على الشبكة نفسها، والعنوانُ = IP الخادم.
- البصمةُ على المحاكّي: أضِع بصمةً وهميّة من Extended controls ← Fingerprint.
- الطابعةُ الحراريّة على المحاكّي لا تعمل (لا بلوتوث) — جرّبها على جهازٍ حقيقيّ.
- عند فشل مزامنة Gradle تحقّق من الوصول إلى `google()` و`mavenCentral()`.

## ١١) حدود النسخة الحاليّة (مقصودة)

- الطابعاتُ: الأجهزةُ **المقترنة** فقط (لا اكتشاف) — الاقتران من إعدادات النظام.
- لا مزامنة خلفيّة تلقائيّة للطابور: إعادةُ الإرسال بضغطة زرّ (المندوبُ يرى ماذا وصل).
- الإشعاراتُ محليّةُ العرض لحظةَ التحديث — لا FCM (الخادمُ لا يوفّره).
- تعليمُ «كلِّ» الإشعارات نداءٌ متكرّر لكلِّ إشعار (لا تجميعَ في الخادم).
