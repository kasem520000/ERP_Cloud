# التدقيق الميداني — إعادة تشغيل التطبيق ضد الخادم الحقيقي

> التاريخ: 2026-10-20 · الأداة: `apps/api/test/android-replay.spec.ts`
> (خادم NestJS حقيقي + PostgreSQL 16 مضمّن + عضوية مالك بكامل صلاحيات السجل — 194 كودًا).

## الخلاصة في سطر واحد

**الخادم يقبل كل عمليات الإنشاء التي يرسلها التطبيق كما هي (201)** — فشل المستخدم
في الإنشاء سببه كله في **التطبيق**: صلاحيات بأكواد لا وجود لها في سجل الخادم
(فأزرار وشاشات تختفي حتى للمالك)، وشكل استجابة مختلف عن المتوقع في مسار واحد
(فينهار تحميل شاشة كاملة)، وشاشات لم تُبنَ أصلًا (فواتير المبيعات والمردودات).

## الدليل — جدول إعادة التشغيل الحرفي

### عمليات الإنشاء (بأجسام التطبيق نصًّا)

| الحركة | المسار | النتيجة |
|---|---|---|
| فاتورة مشتريات (مسودّة) ثم ترحيلها | `POST /purchase-invoices` + `/post` | **201 ✓** |
| بضاعة أول المدة ثم ترحيلها | `POST /inventory/vouchers` kind=opening + `/post` | **201 ✓** |
| سند إدخال مخزني | `POST /inventory/vouchers` kind=stock_in | **201 ✓** |
| سند إخراج مخزني | `POST /inventory/vouchers` kind=stock_out | **201 ✓** |
| سند صرف (مصروف) | `POST /vouchers` kind=payment subtype=expense | **201 ✓** |
| سند قبض (عميل) | `POST /vouchers` kind=receipt subtype=customer | **201 ✓** |
| تسوية جرد ثم ترحيلها | `POST /inventory/adjustments` + `/post {approved:true}` | **201 ✓** |
| فاتورة مبيعات POS | `POST /pos/checkout` | **201 ✓** |
| فاتورة مبيعات مكتبية (مسودّة) | `POST /sales/invoices` | **201 ✓** |
| مردود مشتريات | `POST /purchase-invoices` kind=purchase_return | **201 ✓** (المسار نفسه!) |
| منصرف موظف | `POST /hrm/adjustments` | **201 ✓** |
| مسير رواتب | `POST /hrm/payroll/runs {yearMonth}` | **201 ✓** |

ملاحظتا سلوك خادم مكتشفتان:
- **تسوية الجرد**: الترحيل يرفض بلا `{approved:true}` — «Stock adjustments require
  approval before posting». التطبيق كان يرسلها صحيحة.
- **ترحيل فاتورة مبيعات فورية النقد**: يتطلب حساب صندوق/بنك (`settlementAccountId`)
  أو `settlement:'credit'` للآجل.
- **مردود المبيعات** يتطلب فاتورة **مرحّلة** مصدرًا: `POST /sales/invoices/{id}/return`
  بعد `/post`.

### أشكال استجابات القراءة (مصفوفة خام مقابل غلاف `{data}`)

| المسار | الشكل الفعلي | توقع التطبيق سابقًا | النتيجة |
|---|---|---|---|
| `/hrm/adjustments` | **`{data:[…]}`** | مصفوفة خام | ❌ **انهيار تحميل شاشة المنصرفات** |
| `/hrm/payroll/runs` | `{data:[…]}` | غلاف | ✓ |
| `/hrm/salary-payments` | `{data:[…]}` | غلاف | ✓ |
| `/accounts`, `/branches`, `/cash-locations`, `/warehouses`, `/permissions`, `/pos/offline-data`, `/me` | `{data:…}` | غلاف | ✓ |
| `/purchase-invoices`, `/inventory/vouchers`, `/vouchers`, `/inventory/adjustments`, `/inventory/levels`, `/parties`, الكتالوج، `/hrm/employees·departments·jobs·adjustment-types`, `/sales/salesmen`, `/sales/invoices`, `/reports` | مصفوفة خام | مصفوفة خام | ✓ |

القاعدة المستخلصة (وهي نفسها قاعدة تطبيقات الويب في `packages/web-core`):
**الغلاف غير موحّد بين المتحكمات — العميل يجب أن يتقبل الشكلين.** تطبيقات الويب
تفكّ الغلاف بصمت (`unwrap`); التطبيق كان يفترض شكلًا واحدًا فكان أول انحراف قاتلًا.

## الأعطال الجذرية المكتشفة في التطبيق

1. **أكواد صلاحيات لا وجود لها في سجل الخادم** (`packages/contracts/src/permissions.ts`
   — 194 كودًا هو الكل، ولا `*` للمالك بل تُفصَل كلها):
   - الدرج: `distribution.view` و`collection.view` و`sales.price.manage`
     → **6 شاشات مخفية عن الجميع بما فيهم المالك**: التوزيع والمناديب،
     العهدة والإقفال، أوامر التحميل، تقارير التوزيع، التحصيل، أسعار العملاء.
   - الرواتب: `payroll.run.create`/`payroll.post`/`payroll.pay`
     → أزرار الإنشاء/الترحيل/الصرف مخفية. الصحيح: `hrm.manage` و`hrm.payroll.post`.
   - المنصرفات: `payroll.adjust.create` → مخفي. الصحيح: `hrm.manage`.
2. **`rawList` يفترض مصفوفة خامًا دائمًا** → مسار `/hrm/adjustments` الملفوف
   `{data}` يفجّر التحميل كله (والشاشة «كل شيء أو لا شيء» في `loadStaff`)
   فتخسر القائمة **وبيانات نموذج الإنشاء معًا**.
3. **لا شاشة فواتير مبيعات** (غير POS) ولا مردودات — والخادم يدعمها كاملة.
4. الأصناف/المجموعات/الوحدات في شاشة واحدة — المالك يريدها ثلاث شاشات.
5. الدرج قائمة مسطحة طويلة — المالك يريدها حاويات (محاسبة/مستودعات/…).
6. نصوص خام تظهر للعميل (`stock_transfer` وأمثالها) في التقارير والوثائق.
7. ردود الخادم تظهر في شريط جانبي لا في وسط الشاشة.

## القرارات المعمارية الناتجة

- **فكّ غلاف مزدوج في `rawList`** (مثل `web-core/api.ts`): مصفوفة خام أو
  `{data:[…]}` أو `{items:[…]}` — كله مقبول. يُطبَّق على كل قوائم القراءة.
- **الأزرار لا تختفي بصمت**: عند غياب الإذن يظهر الزر معطّلًا مع اسم الصلاحية
  بالعربية («تحتاج صلاحية: إدارة الموظفين»).
- **مواصفة إعادة التشغيل تُصبح اختبار انحدار دائمًا** في CI.
