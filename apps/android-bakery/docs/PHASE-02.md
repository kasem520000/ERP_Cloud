# المرحلة 2 — عرض وتعديل في كل الشاشات

> الحالة: ⬜ مخطّطة · تُنفَّذ بعد اعتماد المرحلة 1 من المالك

## القاعدة

كلُّ كيانٍ يظهرُ في قائمةٍ يجبُ أن يُفتَحَ **بطاقةَ عرضٍ** تفصيليّة، وكلُّ ما
يقبلُ الخادمُ تعديلَه يظهرُ له زرُّ **تعديل** — لا شاشةَ عرضٍ فقط.

## مصفوفة التعديل (ما يقبله الخادم فعلًا — من المتحكمات)

| الكيان | التعديل | الملاحظة |
|---|---|---|
| مسودّة فاتورة مشتريات | `PATCH /purchase-invoices/{id}` | قبل الترحيل فقط |
| مسودّة فاتورة مبيعات | `PATCH /sales/invoices/{id}` | قبل الترحيل فقط |
| فرع | `PATCH /branches/{id}` | **نُفِّذ في المرحلة 1** |
| مندوب مبيعات | `PATCH /sales/salesmen/{id}` | العمولات والهاتف والمستودع |
| عضويّة مستخدم | `PATCH /memberships/{id}` | الحالة — **نُفِّذ سابقًا** |
| دور | `POST /roles/{id}/permissions` | **نُفِّذ سابقًا** |
| مستودع | `PATCH /warehouses/{id}` | |
| خزينة | `PATCH /cash-locations/{id}` | |
| صنف/مجموعة/وحدة | `PATCH /organization/catalog/...` | يُتحقق من المسارات عند التنفيذ |

## خارج نطاق التعديل (قرار خادم لا يُخترق)

- المستنداتُ المرحّلة لا تُعدَّل — تُبطأ أو يُنشأ مردود؛ هذا قيدُ نظامِ قيدٍ
  مزدوج، لا نقصُ تطبيق.

## ترتيب التنفيذ المقترح

1. بطاقاتُ عرضٍ تفصيليّة لكل قائمة (مستندات المشتريات والمبيعات والسندات
   والتسويات — سطورُها كاملةً من `GET .../{id}`).
2. تعديلُ المسودّات (المشتريات ثم المبيعات).
3. تعديلُ المناديب (العمولات).
4. تعديلُ المستودعات والخزائن في `OrgScreen`.
5. كلُّ تعديلٍ يمرُّ من مواصفة إعادة التشغيل قبل دمجه — القاعدةُ الحاكمةُ
   رقم 5 في `00-ROADMAP.md`.
