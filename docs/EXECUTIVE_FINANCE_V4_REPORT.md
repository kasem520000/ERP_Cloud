| `recharts` | مخططات اللوحة | MIT | موجودة مسبقاً |
| `lucide-react` | أيقونات موحّدة | ISC | موجودة مسبقاً |
| `@fontsource/tajawal`, `inter`, `jetbrains-mono` | العربية + اللاتينية + الأرقام | OFL | أُضيفت لبوابة العملاء فقط |

| `@erp/ui` | نظام التصميم الوحيد | داخلي | موجود |

**لا توجد أي مكتبة أو مكوّن يتطلب اشتراكاً مدفوعاً، ولا مفاتيح ترخيص.**

**بخصوص shadcn/ui:** المستودع يملك بالفعل نظام تصميم داخلياً واحداً (`@erp/ui`) يغطي الأزرار والبطاقات والجداول والنوافذ والتبويبات والتوست. إضافة shadcn/Radix كانت ستنشئ **نظامَي مكوّنات متوازيين** لنفس الوظيفة، ويخالف شرط «لا مكتبتان لنفس العمل» ويضاعف مخاطر لمس شاشات الأعمال. لذلك وسّعنا المكتبة القائمة بنفس فلسفة shadcn (رموز دلالية، مكوّنات صغيرة، حالات وصول واضحة)، واستخدمنا Motion الموجود أصلاً بدل إضافة نسخة ثانية منه. رُوجعت وثائق shadcn وMotion UI قبل القرار.

## 3. نظام الحركة والتفاعل

- **انتقال الصفحات:** 240ms في staff/platform-admin (framer-motion، مفتاح المسار)، و220ms CSS في bakery/portal. لا تأخير للتنقّل، وتُلغى بالكامل عند `prefers-reduced-motion`.
- **ظهور متدرّج:** `Reveal` للأقسام و`Kpi` بفواصل 0/0.1/0.2/0.3s، مرة واحدة عند الدخول (`once`).
- **CountUp:** على مؤشرات اللوحة فقط، يبدأ عند ظهورها، ويُحدَّث من القيمة المعروضة لا من الصفر عند تغيّر البيانات، ويقفز مباشرة عند تقليل الحركة.
- **الأزرار:** hover (رفع 1px)، active (scale 0.985)، focus ring، disabled، وسبينر تحميل + `aria-busy` + `disabled` لمنع الإرسال المزدوج.
- **القوائم/النوافذ:** قوائم منسدلة بحركة `menu-pop`، شريط جوال ينزلق، `Modal`/`Drawer`/`ConfirmDialog` بحركة دخول وخروج، Escape ونقرة خارجية، قفل تمرير الصفحة.
- **التوست:** AnimatePresence، `role=status/alert`، إغلاق يدوي.
- **الرسوم:** tooltips مخصّصة، حركة 800ms، تحديث عند تغيّر البيانات.
- **الحالات:** Skeleton shimmer، EmptyState، ErrorBox، Loading؛ لا نجاح وهمي — كل نجاح يأتي بعد استجابة الخادم.
- **الأداء:** transform/opacity فقط، بلا WebGL/3D، الظلال الثقيلة محصورة في البطاقات الأساسية، و`will-change` محدود.
- **RTL:** خصائص منطقية، قلب تلقائي لأيقونات الاتجاه، تعديل تدرّج القائمة النشطة، واختبارات وحدة لـ`dirFor('ar') === 'rtl'` و`dirFor('en') === 'ltr'`.

## 4. ما لم يُلمس (حماية الوظائف)

- لم تُعدَّل معادلات الضريبة/الخصم/الإجماليات، ولا الترحيل/الإلغاء، ولا عقود API، ولا مخطط قاعدة البيانات، ولا المصادقة/الصلاحيات، ولا سلوك حفظ/تعديل الفواتير، ولا بيانات المستخدمين/المنشآت.
- كل التغييرات عرضية (CSS/JSX/أيقونات) عدا تصحيح واحد لرمز صلاحية في واجهة اللوحة: `accounting.view` (غير موجود في سجل العقود) ← `accounting.reports.view` (رمز مسجّل). أوقفه حارس `permission-codes` وعاد أخضر.
- حارس أداء التسويق كان يقيس مفتاح Next الداخلي `/layout` كأنه صفحة عامة؛ أُضيف إلى `UNMEASURED_ROUTES` لأنه حزمة الجذر المشتركة المحسوبة أصلاً داخل كل مسار عام. لم تُرفع أي ميزانية صفحات.

## 6. حدود التحقق (ما لم يُنفَّذ)

**لم يُجرَ اختبار متصفح حقيقي.** لا يوجد Chromium/Playwright عامل في البيئة: حُزِّم `@sparticuz/chromium` لكنه فشل لنقص مكتبات النظام (`libnspr4.so`)، و`apt` محجوب. لذلك:

- لم تُؤخذ لقطات شاشة، ولم تُختبر بالنقر: القوائم، النوافذ، الوضع الداكن/الفاتح، تبديل اللغة، حفظ النماذج، الأخطاء، الشبكة، Console، ولا أحجام الجداول والفواتير.
- الصفحات المحمية (staff `/`, platform-admin، bakery) تصيّر SSR فقط هيكل «جارٍ التحقق…»، فلا يمكن لـcurl كشف تخطيطها النهائي.
- التحقق البصري الوحيد هو فحص CSS المبني وSSR للصفحات العامة، إضافة إلى الاختبارات الوحدية والحراس.

### فجوات معروفة

1. بعض الشاشات التشغيلية القديمة ما زالت تحتوي إيموجي داخل نصوص الحقول/العناوين (مثل `cash-customer-picker`, `cash-location-master`, `accounting/periods`)؛ استُبدل إيموجي القشرة والحالات فقط.
2. بوابة العملاء والمخابز عربية فقط (لا مبدّل لغة)؛ محتوى شاشات staff عربي أولاً مع ترجمة القشرة والتنقّل. لم تُضف ترجمة كاملة لكل نص.
3. النسخ المحلية القديمة من مكوّنات UI داخل staff/platform-admin ما زالت موجودة ومُعاد تنسيقها؛ توحيدها الكامل في `@erp/ui` مهمة لاحقة لتجنّب كسر APIs الشاشات.
4. `apps/*/globals.css` تحتفظ بطبقات v3 سابقة أسفل طبقة v4؛ لا تضر، لكن تنظيفها سيقلّل الحجم.
5. لا توجد لقطة بصرية baseline ولا اختبار انحدار بصري (البيئة لا تسمح).

## 7. الخلاصة

اكتملت الهوية البصرية v4 على التطبيقات الخمسة الواجهية: **الموظفون، لوحة المنصة، بوابة العملاء، الموقع التسويقي، المخابز**، من خلال نظام رموز واحد ومكوّنات مشتركة، مع دعم RTL/LTR، وضع داكن/فاتح، حركة محترمة لتقليل الحركة، وحماية كاملة لمنطق الأعمال. البناء والأنواع واللينت والاختبارات (512) خضراء جميعاً. التحقق البصري التفاعلي في متصفح حقيقي يبقى غير منفَّذ في هذه البيئة، وهو الحدّ الذي لا ينبغي تجاوزه في التقرير.
