# خطة التنفيذ الحية

## معيار الحالة
`NOT_STARTED` / `IN_PROGRESS` / `BLOCKED` / `IMPLEMENTED` / `VISUALLY_VERIFIED` / `FUNCTIONALLY_VERIFIED` / `DONE`. أعمدة الفحص الجزئي قد تستخدم `CHECKED_PUBLIC` (السطح العام فقط)، `MOCKED_ONLY` (اعتراض وهمي)، `RTL_CHECKED` (العربية فقط)؛ ليست مرادفاً لـDONE. مدخل السجل = route، وليس حالات الشاشة؛ لا تُرقَّى حالة الفحص البصري اعتماداً على build. لا `DONE` قبل فتح الصفحة في المتصفح بعد التعديل والتحقق من التفاعلات والاتجاه. أعِد توليد الجرد بـ`node scripts/ui-screen-registry.mjs`؛ تحقق من تزامنه بـ`--check`. الخطوات تتوقف عند غياب دليل، لا تُخفى الصفحات المحجوبة.

## المراحل والبوابات
1. **الجرد — بدأ/مكتمل على مستوى ملفات route فقط**: استخرج 298 entrypoint من 5 تطبيقات؛ افحص القشرة/المكونات/ملفات CSS والاختبارات والروابط غير المرئية. القبول التالي: تدقيق كل روابط التنقل والإجراءات والحالات الداخلية مقابل السجل، وتوثيق الحالات غير المرتبطة بمسار. لا تفترض أن اكتمال اكتشاف ملفات route يعني اكتمال كل السيناريوهات.
2. **المعمارية — بدأت**: اعتماد `@erp/ui` الحالي مصدراً وحيداً؛ الحفاظ على طبقات CSS الخاصة بكل تطبيق فقط عند الحاجة، وضمان أن بوابة العملاء تستخدم نفس العقد. أضف قواعد تسمية semantic للألوان والاتجاه والقياسات، وقرر استثناءات التسويق والطباعة محلياً.
3. **المحرك — بدأت**: وصل البوابة بالرموز/ThemeScript/Provider، وقِس CSS بعد البناء في الوضعين. أضف فحص drift لا يمنع الاستثناءات الموثقة. القبول: مكونات وتخطيطات حقيقية تتغير مع تغيير الرموز الفاتحة/الداكنة، مع اختبارات regression.
4. **المشتركات**: shell/النماذج/الجداول/الحوارات في staff ثم platform-admin ثم bakery ثم marketing والبوابة. اختبر الحالات disabled/error وscroll وprint وmobile وRTL. لا تستبدل منطق Auth/permissions.
5. **ترحيل الشاشات على دفعات**: البوابة (10 شاشات مرئية + redirect)، ثم platform-admin (38)، bakery (11)، marketing (37)، staff (201) بحسب الوحدة: الدخول، المالية، المخزون، الموارد البشرية، نقاط البيع، الإعدادات وباقي الوحدات. لكل دفعة سجل «قبل / تغيير طبقة العرض / بعد / حالة البيانات / أحجام viewport / RTL/LTR / interactions». صفحات `[id]` تختبر بموجود/غير موجود، والإذن الممنوع والحالات الفارغة؛ لا تعدل العقود/الحسابات.
6. **فحص حقيقي**: شغّل التطبيقات مع API وبيانات اختبار معتمدة وPlaywright/متصفح إن توفر، التقط نتائج وصور بعد كل إصلاح، اختبر مفاتيح التنقل وConsole والشبكة (لا عمليات ترحيل أو دفع). المستحيل الوصول إليه يبقى BLOCKED مع سبب محدد.
7. **تسليم**: `--check` للجرد + فحص drift + lint/typecheck/test/build للواجهات + مراجعة diff للتأكد من عدم لمس accounting/API/DB. أحصِ DONE فقط؛ وافصل عن IMPLEMENTED وBLOCKED.

## تقدّم الدفعة الحالية (2026-10-18)

Chromium صار متاحاً مؤقتاً في `.cache/browser`، والعائق الباقي جلسات API/DB تجريبية مرخّصة وبيانات حالات الشاشات، لا نقص المتصفح. راجع `TEST_REPORT.md` والصور. المرحلة التالية: ترحيل داخل صفحات staff/platform على دفعات وحدة-بوحدة وفحص سيناريوهات صلاحيات معزولة قبل رفع الحالة.
