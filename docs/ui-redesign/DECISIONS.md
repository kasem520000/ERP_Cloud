# سجل القرارات

- **2026-10-18 / D-01**: لا يُنشأ design system ثانٍ. `@erp/ui` v3 موجود بمتغيرات semantic وlight/dark ومكتبة كبيرة. يجب إغلاق فجوة بوابة العملاء أولاً بدلاً من إعادة كتابة الحزمة. صفحات staff/marketing لا تعتبر مرحّلة لمجرد استيراد `tokens.css`.
- **D-02**: registry يُشتق من App Router مع ID hash ثابت من app+route؛ حالات المراجعة تُحفظ عند إعادة التوليد. استثناء 404 المخصصة يسجّل منفصلاً؛ redirect الجذر يسجل لكن لا شاشة مرئية. تبقى الحالات الداخلية خارج عدد المسارات وتُختبر داخل كل صف.
- **D-03**: هوية النظام الافتراضية `نظام سحاب المملكة للحلول المحاسبية`. علامة المستأجر white-label واسم الموقع القادم من API لها أولوية متعمدة؛ لا يُغيّر محتوى قاعدة بيانات العملاء أو عقود API بمجرد إعادة التسمية. الاستثناءات مثل اسم مُصدر MFA واسم package التقني تُراجع منفصلة لأنها تؤثر على أجهزة المصادقة/التكاملات.
- **D-04**: تبديل الثيم عبر المفتاح الموجود `erp.theme` فقط. طباعة الفواتير تبقى محايدة وواضحة بصرف النظر عن الثيم. التسويق يحتفظ بتخطيط landing مختلف فوق نفس الرموز.
- **D-05**: لا يُطلب تعديل قاعدة بيانات أو نشر/دمج. توثيق الاختبارات المتعذرة أفضل من تقرير إنجاز غير قابل للإثبات.
- **D-07**: ملف marketing كان يستورد `tailwindcss` و`@erp/ui/tokens.css` بلا PostCSS؛ أصناف ThemeToggle والمعرض لم تُولّد. أُضيف `postcss.config.mjs` و`@source`، واجتاز build واختبار الميزانية، لكن بقية صفحات التسويق تحتاج فحصاً بصرياً فلا يُعد هذا ترحيلاً لجميعها.
- **D-06**: إزالة مكوّن `components/card.tsx` المحلي في بوابة العملاء لصالح `SummaryStat`، واستخراج layout primitives مشتركة في `@erp/ui/page`. لم تُحوّل صفحات staff/console إلى `IMPLEMENTED` لأن تغيير رأسها المشترك لا يضمن صلاحية الجداول/النماذج الداخلية. تم اختيار subpath خفيف بعد أن رفع الاستيراد من barrel في login حجم أول تحميل من 105kB إلى 277kB؛ بعد التعديل عاد إلى 105kB. مسارات التسويق لا تُفرض عليها قشرة ERP التشغيلية؛ تظل landing ذات محتوى CMS.
