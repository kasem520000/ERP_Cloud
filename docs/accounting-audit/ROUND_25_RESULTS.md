**الغرض:** تنفيذ فعلي (شاشة + API + DB) لمسارات لم تُلمس في R10–R24: التقريب وعُشر الهللة، ثقة الخادم بالعميل في الضريبة والسعر، قوائم الأسعار، التحويل النقدي والمناقلة بين فرعين، الضريبة الانتقائية، الاستقطاع على الشراء، المخزون السالب وقيمته عند الصفر، التقرير المخصص، الإعدادات الميتة (مع إرجاعها)، والقوائم الختامية (إقرار الضريبة، الدخل، المركز المالي، التقييم، الأطراف). خط الأساس = R24 DB-038 = `R25-DB-000-BASELINE`؛ التوقعات محسوبة قبل التشغيل في `CONTINUITY_R25.md` §1.

## 0. عوائق هذه الجولة
- **شاشة التحويل النقدي ترشّح صناديق الوجهة بفرع المصدر** (`treasury/transfers/page.tsx` L125) فلا يمكن اختيار صندوق الفرع الثاني من الشاشة؛ وُثّق الخيار الفعلي (`R25-CT-CROSS-SCREEN-options.json` + صورة) ثم نُفّذ التحويل عبر API من الجلسة نفسها — API يقبله بلا فحص (ACC-112).
- **الاستقطاع على المشتريات** لا شاشة له ولا حساب في ملف الترحيل؛ اختُبر عبر API وأعطى 422 `PURCHASE_WITHHOLDING_MANUAL_POSTING` كما توقّع الكود — المسودة باقية بلا رقم.
- تغيير الإعدادات الثلاثة (`vat.default_rate_percent`, `pricing.price_includes_vat`, `allow_negative_stock`) كان ضرورياً لإثبات أنها ميتة؛ **أُعيدت في الخطوة نفسها** (`restore-*` 200؛ DB-023/024 تؤكد 15 / false / false) وسُجلت الستّ تغييرات في `audit_log` (`settings/update`). المسودتان الناتجتان (SI بلا ضريبة 20، SI 23 + 3.45) وSOU-000003 تُركت مسودات بلا أثر محاسبي.
- `GET /statements/trial-balance?branchId=` تجاهل الفلتر لأن المعامل الصحيح `branch_id` (خطأ أداة لا نظام)؛ الحكم على الفروع بُني على `journal_entries.branch_id` مباشرة (`R25-journal-branches.json`).
- اللقطات لا تضم `branch_id` لرؤوس القيود؛ أُضيف استعلام مباشر كدليل مستقل.
